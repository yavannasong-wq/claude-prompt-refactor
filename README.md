# prompt-refactor

一个 Claude Code Skill：把"一坨大段文本"式的提示词，重构成**用 XML 标签隔离语义块**的结构化 Prompt。

> 判断标准只有一句：
> **如果你自己读 Prompt 都分不清哪句是准则、哪句是政策、哪句是数据，模型一定也分不清。**

---

## 它解决什么问题

大多数生产环境里的 Prompt 都长得像这样：

```
你是一名有经验的客服。忘掉你以前的知识，只用下面资料。
以下文章可能相关也可能不相关……（夹着 cookie 政策、相关推荐）
回答要简洁，别用 emoji。客户是 postpaid，热点 5GB。
如果是账单问题转人工。**CRITICAL：务必算准！**
```

问题不在"没加 XML"，而在：

| 症状 | 后果 |
|---|---|
| 角色、规则、政策、数据、语气混成一段 | 模型分不清哪条是指令、哪条是数据 |
| 口径没定义（怎么算、按什么基准） | 每期结果都不一样，无法对比 |
| 要的指标源数据里没有 | 模型开始编造 |
| 旧模型遗留的"防御性补丁" | 新模型过度避险、隐瞒已知信息 |
| 只有单向禁令（"不要…"） | 模型极端保守，该做的也不做 |
| 没有输出契约 | 输出结构随机，没法归档 |

这个 Skill 把上述问题拆成**可重复执行的六步流程**。

## 安装

### 方式一：直接装到个人 skills 目录（推荐）

```bash
git clone https://github.com/yavannasong-wq/claude-prompt-refactor-skill.git \
  ~/.claude/skills/prompt-refactor
```

仓库根目录就是 `SKILL.md`，克隆后立刻可用，无需再挪文件。

### 方式二：手动复制

```bash
mkdir -p ~/.claude/skills/prompt-refactor
cp SKILL.md ~/.claude/skills/prompt-refactor/
cp -R references ~/.claude/skills/prompt-refactor/
```

安装后重启 Claude Code（或新开一个会话），`/skills` 列表里应出现 `prompt-refactor`。

## 使用

直接说人话就会触发：

- "帮我改一下这个提示词"
- "把这个 Prompt 结构化一下"
- "用 XML 隔离语义块重构提示词"
- "提示词输出总是不稳定"

也可以显式调用：

```
/prompt-refactor
```

### 触发后会做什么

1. **先查素材**：源数据是否支撑需求？缺字段、口径歧义必须指出，**不替用户假设**；
2. **逐句分类**：输出问题表，每条带原文证据；
3. **套骨架**：`<role> <task> <instructions> <policy> <tone> <documents> <customer_data> <output_format>`；
4. **补三样**：权威性声明、输出契约、不确定性规则；
5. **训诫换结构**：能力缺口 → 工具调用；单向禁令 → 补齐天平另一端；流程堆叠 → 拆多段调用；
6. **给评测**：3–5 条用例 + 一行通过标准 + "一次改一处、全量重跑"。

### 输出长什么样

固定四部分：**诊断 → 重构后的完整 Prompt → 改动对照表 → 评测建议**。
不会只丢给你一段改好的 Prompt——那样你无法判断改动是否有效。

## 一个最小示例

**改前**

```text
你是一名制造车间的设备管理人员。每天需要针对设备的运行情况制作设备分析报告。
报告中包括停机次数，停机时间，设备产量。原始记录保存在excel文档内部。
```

**改后（节选）**

```xml
<role>
你是一名制造车间的设备管理人员（设备工程师），负责对车间设备的日常运行数据做统计分析。
报告的使用者是车间主任与维修班组，用于安排检修与评估设备稳定性。
</role>

<metric_definitions>
<停机时间>
口径：停机时间 = 每日计划可用时长 − 当日运行时长，按设备逐日计算后累加。
禁止使用 24 小时作为扣减基数。
</停机时间>

<设备产量>
口径：当前数据表无产量列时，不计算任何产量数字。
汇总表中该列填"未提供"，并在"数据质量"一节列出为支持产量统计应增加的列。
不得根据运行时长推算或估算产量。
</设备产量>
</metric_definitions>
```

关键不是标签本身，而是：

- "停机时间"到底按 24h 还是计划工时减？——**必须定义**（同一批数据两种口径差 9 倍）；
- "产量"列根本不存在——**必须明确"不计"**，否则模型必然编数字。

## 适用与不适用

**适用**

- 已有 Prompt 输出不稳定、结构混乱、越改越肿；
- 要从旧模型迁移到新模型，需要清理历史补丁；
- 要写报表 / 客服 / 审核类有固定输出的 Prompt；
- 想建立 eval 但不知道从哪开始。

**不适用**

- 从零写全新 Prompt（先用最小骨架，再迭代）；
- 需要工具编排、多 agent 协作的复杂系统设计；
- 只是想让回答"更有创意"——结构化解决不了这个问题。

## 设计来源

方法提炼自 Anthropic 在 **Code w/ Claude** 场次的演讲 *The prompting playbook*（讲者 Margot van Laar），并结合实际改写设备分析报告 Prompt 的案例做了补充：

- XML 标签隔离语义块；
- 清理为旧模型添加的防御性补丁；
- 指令不赋予能力，复杂运算交给工具；
- 业务权衡要给出天平两端；
- 生成 → 评估 → 修复闭环；
- 补充：**先有 eval 再改 Prompt**，以及**缺字段不得编造**。

本仓库是独立整理的方法与模板，不代表 Anthropic 官方。

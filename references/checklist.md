# 自查清单与常见反模式

## 一、重构前（诊断阶段）

- [ ] 我有没有读懂**源数据**？表头、样例行、列含义都核过吗？
- [ ] 用户要的每个指标，源数据里**都有对应字段**吗？缺的列是不是都写了处置规则？
- [ ] 有没有**口径歧义**（分母、时间基准、统计范围）？是否已让用户定义或列为待填？
- [ ] 原文里有没有**两条规则互相冲突**？冲突时有没有写明优先级？
- [ ] 有没有**旧模型遗留的防御补丁**（"绝不要说…""引导用户自己去查…"）？它现在还有必要吗？

## 二、重构中（改写阶段）

- [ ] 第一次是否**只搬运、不改写内容**？
- [ ] 标签名是否**自带说明书**？是否全项目统一？
- [ ] 有没有把**语气**混进业务规则？有没有把**政策**混进数据？
- [ ] 嵌套是否 ≤ 3 层？
- [ ] `必须/务必/CRITICAL/NEVER` 是否都能对应到**结构手段**（字段、工具、判定条件），而不是继续堆字？
- [ ] 单向禁令/单向成本，是否都补上了**天平另一端**？

## 三、重构后（验收阶段）

- [ ] 输出结构是否**固定到可以逐期对比**？
- [ ] 关键数字是否**可复现**（来源标注 / 计算方式）？
- [ ] 数据不足时的**话术**是否明确（"数据不足，无法判断"）？
- [ ] 有没有给出 **3–5 条测试用例 + 一行通过标准**？
- [ ] 是否建议了"**一次只改一处、每次全量重跑**"？

## 四、常见反模式

| 反模式 | 为什么错 | 正确做法 |
|---|---|---|
| **标签表演**：给每句话都套标签 | 增加噪音，标签失去区分度 | 只在**语义类别切换**处加标签 |
| **把训诫装进 `<instructions>`** | 换位置不等于换方法，模型仍只看到"强调" | 改为字段、工具、判定标准 |
| **假角色**："你是一名人类客服" | 不真实，且与"禁止透露 AI 身份"类规则冲突 | 写真实职能角色 + 产出对象 |
| **塞满资料**：整篇网页/手册塞进 `<documents>` | 页脚、推荐、cookie 提示成为噪音 | 只留正文，并在 `<instructions>` 写明忽略无关内容 |
| **无优先级**：两份数据都说"以我为准" | 模型随机选一份 | 用 `<policy>` 显式声明权威顺序 |
| **口径缺失**：让模型"自己判断怎么算" | 每期算法不同，报告不可比 | 在 `<metric_definitions>` 写死公式 |
| **缺字段硬算**：产量列没有还要求产量 | 必然幻觉 | 明确"标注未提供"，并列出应补字段 |
| **一个巨型 Prompt 包打天下** | 复杂约束互相干扰、token 浪费 | 拆成生成 → 评估 → 修复的多段调用 |
| **只改不测** | 无法知道改结构是否有效 | 建 eval，一次改一处，全量重跑 |
